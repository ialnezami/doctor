## Objective

Register the `auditLog` middleware created in Plan 01 on all PHI-bearing routes. Every read, create, update, and delete of Patient, ConsultationNote, Prescription, and LabResult must produce an AuditLog entry.

This plan uses the `auditLog(resourceType, action, getResourceId, getTargetUserId)` middleware factory from `middleware/auditLogger.js`. The factory intercepts `res.json` and writes the audit log after the response is sent.

Purpose: HIPAA requires tracking who accessed what PHI and when. Without this, no audit trail exists for PHI access events.

Output: Updated routes files with `auditLog()` middleware applied to PHI endpoints. No new files created.

<action>

```javascript
const { auditLog } = require('../middleware/auditLogger');
```

Apply to routes:
```javascript
// POST /api/prescriptions — doctor creates
router.post('/', auth, requireRole('doctor'),
  auditLog('Prescription', 'create', (req, res) => res.locals.prescriptionId),
  async (req, res, next) => {
    try {
      const rx = await Prescription.create({ ... });
      res.locals.prescriptionId = rx._id; // capture for audit
      res.status(201).json(rx);
    } catch (err) { next(err); }
  }
);
// Note: auditLog interception fires when res.json() is called, after res.locals is set

// GET /api/prescriptions — list
router.get('/', auth,
  auditLog('Prescription', 'read'),
  async (req, res, next) => { ... }
);

// GET /api/prescriptions/:id

  auditLog('Prescription', 'read', (req) => req.params.id),

);

router.get('/:id/pdf', auth,
```
