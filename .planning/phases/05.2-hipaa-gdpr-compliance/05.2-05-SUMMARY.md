# Phase 5.2 Plan 05: Auth Layer GDPR Hardening Summary

Auth routes and middleware updated to enforce GDPR consent at registration, route login via HMAC blind index, and block erased-user JWT access at the middleware layer.

## Tasks Completed

### Task 1: Consent enforcement + emailHash login (auth routes)

**Commit:** `70f938c`

Changes to `apps/api/src/routes/auth.js`:

- `POST /register` now validates `consentAccepted === true` via express-validator `.custom()`. Missing or false value returns 422 with "You must accept the Terms of Service to register".
- Registration stores `consentVersion` (from `TERMS_VERSION` env var, default `'1.0'`), `consentTimestamp`, `consentIp`, and `dataProcessingAllowed: true` on the new User document.
- Duplicate email check switched from `User.findOne({ email })` to `User.findOne({ emailHash: hmacHash(email) })`.
- `POST /login` switches from `User.findOne({ email })` to `User.findOne({ emailHash: hmacHash(email) })`. Once Plan 10 encrypts the email field, the plaintext lookup would never match ciphertext — this change is deployed first to ensure login works through and after migration.
- Login writes a fire-and-forget `AuditLog` entry with `action: 'login'`.
- Registration writes a fire-and-forget `AuditLog` entry with `action: 'consent'`.
- `POST /google` (new user path): stores consent fields on creation, writes consent AuditLog.
- `POST /google` (link existing user path): switches email lookup to emailHash.

### Task 2: erasedAt check in auth middleware

**Commit:** `8849eea`

Changes to `apps/api/src/middleware/auth.js`:

- Middleware promoted from synchronous to `async`.
- After JWT verification sets `req.user`, a DB lookup (`User.findById(decoded.id).select('erasedAt isSuspended').lean()`) checks the erasure and suspension state.
- `user.erasedAt` non-null → 401 "Account has been erased". GDPR right-to-erasure: the user's JWT is still cryptographically valid until expiry, but the application rejects it immediately.
- `user.isSuspended` → 403 "Account suspended". This check previously only existed in the login route; moving it to middleware enforces it on every authenticated request.
- DB error → 503 "Service temporarily unavailable". Fail-closed: a transient DB outage must not grant access to erased or suspended accounts.
- `.lean()` minimizes Mongoose overhead; `select('erasedAt isSuspended')` limits field fetch.
