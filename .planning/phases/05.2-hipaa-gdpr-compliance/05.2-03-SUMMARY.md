# Phase 5.2 Plan 03: PHI Model Encryption Hooks Summary

AES-256-GCM field-level encryption added to all four PHI-bearing Mongoose models via transparent pre-save / post-init hooks.

## What Was Built

**Patient model** (`apps/api/src/models/Patient.js`):
- Pre-save: encrypts `medicalHistory[]`, `allergies[]`, `conditions[]` (element-wise), `bloodType`, `dateOfBirth` (ISO string), `notes[].content`
- Post-init: decrypts all above; restores `dateOfBirth` as `new Date(decrypted)`
- `dateOfBirth` field type changed to `Mixed` (stores encrypted string at rest)
- 6 `isModified()` guards

**ConsultationNote model** (`apps/api/src/models/ConsultationNote.js`):
- Pre-save: encrypts `content`, `aiAssist.patientSummary`
- Post-init: decrypts both
- `icdCodes`, `flags` left plaintext (metadata, not PHI content)

**Prescription model** (`apps/api/src/models/Prescription.js`):
- Pre-save: encrypts `instructions`, all `medications[].{name,dosage,frequency,duration}` via `MED_FIELDS` constant
- Post-init: decrypts same; sentinel check in pre-save guards against re-encryption
- `verificationToken` left plaintext (must remain queryable for QR verification)

**LabResult model** (`apps/api/src/models/LabResult.js`):
- Pre-save: encrypts `notes`, `aiInterpretation.summary`, `tests[].value`
- Post-init: decrypts same
- `tests[].name`, `tests[].unit`, `tests[].referenceRange`, `tests[].flag` left plaintext
- Text index `{ 'tests.name': 'text', labName: 'text' }` preserved

## Engineering Notes

**Double-encryption prevention:** Every PHI field write is guarded by `this.isModified(field)`. Without this guard, loading and re-saving a document would encrypt already-encrypted ciphertext, causing irreversible data corruption.

**Zero-downtime migration:** The `fieldEncryption.decrypt` function's `|` sentinel (ciphertext includes `|`, plaintext does not) means existing plaintext records continue to return their values as-is after deployment. No migration script is needed.

**Route impact:** All routes that use `Model.findOneAndUpdate()` on these models bypass pre-save hooks. Plan 04 must refactor those routes to use `.save()` pattern before these encryption hooks protect those write paths.

**Decrypt failure safety:** All `post('init')` handlers have `try/catch`. Errors are logged with doc `_id` only — never PHI content — and execution continues so reads never crash.
