## Objective

Add compliance fields to the User model without breaking any existing functionality:
1. `emailHash` — HMAC-SHA256 blind index on email, required for login after email encryption is deployed in later phases.
2. Consent fields — track patient's explicit data processing consent per GDPR Article 7.
3. `erasedAt` — timestamp set during GDPR erasure; checked in auth middleware (Plan 06) to reject tokens of erased users.

This plan only modifies `User.js`. Auth routes that query by email are updated in Plan 05.

Purpose: These fields must exist on the model before Plans 05 (auth routes) and 07 (erasure) write to them.

Output: Updated `apps/api/src/models/User.js`.

```javascript
consentVersion:      { type: String, default: null },      // e.g. "2024-01" — bump when terms change

// Email blind index for login lookup after email is encrypted

// Populated by pre-save hook below; unique sparse index for login queries
emailHash: { type: String, default: null },
```

Add unique sparse index after the existing 2dsphere index:
```javascript

```

Add a new pre-save hook AFTER the existing bcrypt hook (do not merge into it):
```javascript
const { hmacHash } = require('./utils/blindIndex');

// Wait — this is a model file under models/, so the relative path to utils/ is:
const { hmacHash } = require('../utils/blindIndex');

userSchema.pre('save', function (next) {
  // Update emailHash whenever email changes
  // This fires on new user creation and on email update
  if (this.isModified('email') && this.email) {
    try {
      this.emailHash = hmacHash(this.email);
    } catch (err) {
      // BLIND_INDEX_KEY misconfigured — fail loudly to prevent stale emailHash
      return next(err);
    }
  }
  next();
});
```
