# Phase 5.2 Plan 04: findOneAndUpdate Elimination for Encrypted Models — Summary

Eliminated all `findOneAndUpdate`/`findByIdAndUpdate` calls on the two encrypted Mongoose models (Patient, ConsultationNote) so that the `pre('save')` encryption hooks installed in Plan 03 actually fire on every PHI write.

## Tasks Completed

| Task | Description | Commit |

| 1 | Refactor patients.js — PATCH /me/location, /me/profile, /me/photo to findOne+save() | 3fb524a |
| 2 | Refactor notes.js — PATCH /:apptId/notes/:noteId to findOne+save() | 16ccf97 |

## What Changed

**apps/api/src/routes/patients.js**

- `PATCH /me/location`: replaced `Patient.findOneAndUpdate(..., { $set: update }, { new: true })` with `Patient.findOne({ userId })` + direct field mutation + `patient.save()`. Impact: city/homeLocation are not PHI but standardized for consistency and to eliminate concurrency race with /me/profile.
- `PATCH /me/profile` (CRITICAL): replaced `Patient.findOneAndUpdate()` with `findOne + mutate + save()`. This is the fix that actually causes `bloodType`, `dateOfBirth`, `allergies`, and `conditions` to be encrypted before being persisted. Before this change, all four PHI fields were written to MongoDB in plaintext despite the encryption hook.
- `PATCH /me/photo`: replaced `Patient.findOneAndUpdate()` with `findOne + mutate + save()`. photoUrl is not PHI, but standardized for consistency.

**apps/api/src/routes/notes.js**

- `PATCH /:apptId/notes/:noteId` (CRITICAL): replaced `ConsultationNote.findOneAndUpdate()` with `findOne + mutate + note.save()`. This causes the `content` field (PHI) to be encrypted before each update. The `{ runValidators: true }` option from the old call is replaced by Mongoose schema validators that fire automatically on `.save()` (maxlength: 5000 on content, enum on visibility).
- `DELETE /:apptId/notes/:noteId`: `findOneAndDelete` preserved — deletes do not write data and do not bypass save hooks.
- `POST /:apptId/read`: `ReadEvent.findOneAndUpdate` preserved — ReadEvent is not an encrypted model.

## Authorization Preservation

All ownership and role checks are unchanged:
- `requireRole('patient')` on all three patients.js mutation routes
- Doctor-only guard (`req.user.role !== 'doctor'`) on notes.js PATCH
- Appointment ownership filter (`getApptForDoctor`) on notes.js PATCH
- Note ownership filter (`appointmentId: appt._id`) in `ConsultationNote.findOne` query
