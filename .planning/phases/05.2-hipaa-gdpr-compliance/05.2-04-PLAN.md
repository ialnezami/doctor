## Objective

The Mongoose `pre('save')` encryption hooks installed in Plan 03 only fire when `.save()` is called on a document instance. Any route that uses `Model.findOneAndUpdate()` or `Model.findByIdAndUpdate()` bypasses the hook entirely — the update is written to MongoDB **in plaintext** even though the model has encryption hooks.

This plan eliminates all `findOneAndUpdate`/`findByIdAndUpdate` calls on the four encrypted models (Patient, ConsultationNote) by refactoring them to the `findById` + mutate + `.save()` pattern. Prescription and LabResult routes do not currently use `findOneAndUpdate` on PHI fields.

Routes that use `findOneAndUpdate` on NON-encrypted fields (e.g., `PATCH /api/auth/me` updates `name` only — not a PHI field) are left unchanged.

Purpose: Without this refactor, `PATCH /api/patients/me/profile` would write bloodType, allergies, conditions in plaintext to MongoDB, silently bypassing the encryption hook.

Output: Updated `apps/api/src/routes/patients.js` and `apps/api/src/routes/notes.js`.

<action>
In `apps/api/src/routes/patients.js`, refactor the following three routes:

**Route 1: `PATCH /api/patients/me/location`**

Current code uses `Patient.findOneAndUpdate({ userId: req.user.id }, { $set: update }, { new: true })`.
City and homeLocation are NOT PHI, so the privacy impact is low. However, if this route runs concurrently with `/me/profile`, two simultaneous writes could race. Standardize to `.save()` for consistency:

```javascript
router.patch('/me/location', auth, requireRole('patient'), async (req, res, next) => {
  try {
    const { city, lat, lng } = req.body;
    if (!city) return res.status(422).json({ message: 'city is required' });

    const patient = await Patient.findOne({ userId: req.user.id });
    if (!patient) return res.status(404).json({ message: 'Profile not found' });

    patient.city = city;
    if (lat != null && lng != null) {
      patient.homeLocation = { type: 'Point', coordinates: [parseFloat(lng), parseFloat(lat)] };
    }
    await patient.save();
    res.json(patient);
  } catch (err) { next(err); }
});
```

**Route 2: `PATCH /api/patients/me/profile`** (CRITICAL — updates encrypted PHI fields)

Current code uses `Patient.findOneAndUpdate(..., { $set: update }, { new: true })`. This bypasses encryption hooks on bloodType, dateOfBirth, allergies, conditions.

Refactor:
```javascript
router.patch('/me/profile', auth, requireRole('patient'), [
  body('bloodType').optional().isIn(BLOOD_TYPES).withMessage('invalid bloodType'),
  body('dateOfBirth').optional().isISO8601().withMessage('dateOfBirth must be ISO8601'),
  body('allergies').optional().isArray().withMessage('allergies must be an array'),
  body('allergies.*').optional().isString().trim(),
  body('conditions').optional().isArray().withMessage('conditions must be an array'),
  body('conditions.*').optional().isString().trim(),
], validate, async (req, res, next) => {
  try {
    const { bloodType, dateOfBirth, allergies, conditions } = req.body;

    const patient = await Patient.findOne({ userId: req.user.id });
    if (!patient) return res.status(404).json({ message: 'Profile not found' });

    // Only set fields that were provided — isModified() in hook fires on these
    if (bloodType !== undefined)   patient.bloodType   = bloodType;
    if (dateOfBirth !== undefined) patient.dateOfBirth = new Date(dateOfBirth);
    if (allergies !== undefined)   patient.allergies   = allergies;
    if (conditions !== undefined)  patient.conditions  = conditions;

    await patient.save(); // triggers pre-save encryption hook
    res.json(patient);    // post-init hook already decrypted on the findOne above;
                          // after save(), return the in-memory doc (already plaintext)
  } catch (err) { next(err); }
});
```

**Route 3: `PATCH /api/patients/me/photo`** (updates photoUrl — not PHI, but standardize for consistency)

```javascript
router.patch('/me/photo', auth, requireRole('patient'), upload.single('photo'), async (req, res, next) => {
  try {
    if (!req.file) return res.status(422).json({ message: 'photo file required' });
    const photoUrl = await uploadBuffer(req.file.buffer, 'mediconnect/patients');

    const patient = await Patient.findOne({ userId: req.user.id });
    if (!patient) return res.status(404).json({ message: 'Patient profile not found' });

    patient.photoUrl = photoUrl;
    await patient.save();
    res.json({ photoUrl });
  } catch (err) { next(err); }
});
```

<action>
In `apps/api/src/routes/notes.js`, refactor the note update route (line 81) to use `findById` + mutate + `.save()`. The delete route uses `findOneAndDelete` — this does NOT bypass save hooks (it's a delete, not a write), so it can remain as-is.

**Route: `PATCH /api/appointments/:apptId/notes/:noteId`** (CRITICAL — updates `content` which is encrypted)

Current code:
```javascript
const note = await ConsultationNote.findOneAndUpdate(
  { _id: req.params.noteId, appointmentId: appt._id },
  { $set: update },
  { new: true, runValidators: true }
);
```

Refactor to:
```javascript
const note = await ConsultationNote.findOne({
  _id: req.params.noteId,
  appointmentId: appt._id,
});
if (!note) return res.status(404).json({ message: 'Note not found' });

// Apply only provided fields
if (content !== undefined) note.content = content;
if (visibility !== undefined) note.visibility = visibility;

await note.save(); // triggers pre-save encryption on content if modified
res.json({ note });
```

The `{ runValidators: true }` behavior is replaced by Mongoose schema validators that fire on `.save()` by default (maxlength: 5000 on content, enum on visibility). No behavior regression.

Also: The `DELETE /api/appointments/:apptId/notes/:noteId` route uses `findOneAndDelete` — this is acceptable because it deletes the document, so no save hook bypass concern. Leave it unchanged.

Verify `ReadEvent.findOneAndUpdate` in the `POST /:apptId/read` route — ReadEvent is NOT an encrypted model, so it is exempt from this refactor. Leave unchanged.
</action>
