# Phase 09 Plan 1: AI Patient Chatbot Backend Summary

**One-liner:** SSE-streaming triage chatbot with in-memory HIPAA-safe sessions, $geoNear doctor ranking, per-user rate limiting, and Anthropic BAA compliance gate.

## Endpoints Delivered

### POST /api/chatbot/message

**Middleware chain:** `auth → requireRole('patient') → chatbotLimiter → express-validator → handler`

**Request:**
```json
{
  "message": "string (1–2000 chars, required)",
  "lat": "float -90..90 (optional, for doctor geo-ranking)",
  "lng": "float -180..180 (optional)"
}
```

**SSE Response stream (Content-Type: text/event-stream):**
```
data: {"type":"delta","text":"chunk of AI text..."}
data: {"type":"delta","text":"more text..."}
data: {"type":"done","urgency":"soon","specialties":["cardiology"],"summary":"...","emergency":false,"doctors":[...],"specialtyFallback":false}
data: [DONE]
```

**Error event:**
```
data: {"type":"error","message":"Response timed out — please try again."}
data: [DONE]
```

**Auth gates:** 401 (no/invalid JWT), 403 (non-patient role), 422 (validation), 429 (rate limit), 503 (API key missing)

### GET /api/chatbot/doctors

**Query params:** `lat` (required), `lng` (required), `specialty` (optional, max 100 chars), `limit` (optional, 1–20, default 5)

**Response:**
```json
{
  "doctors": [{ "_id": "...", "specialty": "...", "distMeters": 1234, "score": 0.23, "user": {"name": "..."}, ... }],
  "specialtyFallback": false
}
```

### DELETE /api/chatbot/session

**Response:** 204 No Content — clears caller's in-memory conversation history

## Session Store TTL + Cap

| Property | Value |
|----------|-------|
| Store | node-cache (in-memory, single-process) |
| TTL | 1800 seconds (30 min sliding window — resets on each `appendAndSave`) |
| Max messages | 20 (MAX_TURNS) — oldest messages trimmed when exceeded |
| Background eviction | checkperiod: 300 (evicts expired sessions every 5 min) |
| Key | `req.user.id` (JWT sub) — no cross-user access path |
| Persistence | None — intentionally ephemeral (HIPAA: conversation history is PHI) |

Memory estimate: ~20 messages × ~200 tokens × 4 bytes ≈ 16KB/session. At 10,000 concurrent sessions: ~160MB peak.

---

## Rate Limit Key + Threshold

| Property | Value |
|----------|-------|
| Window | 1 hour |
| Max | 30 requests per window |
| Key | `req.user.id` (auth runs before chatbotLimiter) |
| IP fallback | `ipKeyGenerator(req)` — IPv6-safe via express-rate-limit helper |
| Response | 429 + `{ message: 'Chatbot rate limit exceeded — 30 messages per hour allowed.' }` |

---

## SSE Event Schema

| Event | When | Payload |
|-------|------|---------|
| `delta` | Each text chunk from Claude | `{ type: 'delta', text: 'string' }` |
| `done` | After stream + triage parse + doctor query | `{ type: 'done', urgency, specialties, summary, emergency, doctors, specialtyFallback }` |
| `error` | Timeout (25s) or Anthropic API failure | `{ type: 'error', message: 'string' }` |
| `[DONE]` | Stream terminator | Literal string `data: [DONE]` |

**Stream lifecycle:** chatbotService writes `delta` and `error` events, returns accumulatedText. Route writes `done` event and calls `res.end()`. Service never closes the stream (contract enforced by acceptance criteria grep).

## Doctor Ranking

**Pipeline:** `$geoNear → $lookup(users) → $unwind → $match(specialty) → $addFields(scores) → $sort → $limit → $project`

**Score formula:** `score = (0.7 × normalizedDist) + (0.3 × (1 - ratingScore))` — lower = better rank

**Fallback:** If specialty filter yields < 3 results → re-query without specialty, sets `specialtyFallback: true`

**Index used:** `locations.coordinates` 2dsphere index (already exists on Doctor model — no migration needed)
